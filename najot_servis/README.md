# 🚛 NAJOT SERVIS — Telegram-бот сервиса грузовых автомобилей

Система приёма и контроля заявок на ремонт **только грузовых автомобилей**
(тягачи, самосвалы, бортовые, фургоны, рефрижераторы, цистерны, спецтехника, малотоннажные):
**КЛИЕНТ → БОТ → ЗАЯВКА → OWNER → MASTER → РЕМОНТ → СТАТУС → ГОТОВНОСТЬ → УВЕДОМЛЕНИЕ КЛИЕНТА**

Стек: Python 3.11+, aiogram 3 (Telegram Bot API), SQLAlchemy 2 (async), SQLite → PostgreSQL, Claude API (AI-помощник).

## Куда приходят заявки

Все новые заявки приходят в **@Najotservis** (`NOTIFY_TARGETS` в `.env`) и всем владельцам.

* Если @Najotservis — личный аккаунт: откройте с него бота и нажмите **/start** один раз
  (Telegram не позволяет боту писать тому, кто его не запускал). Аккаунт из `OWNER_USERNAMES`
  автоматически получает права владельца — кнопки «Принять», «Назначить мастера» в заявке работают.
* Если @Najotservis — группа или канал: добавьте бота туда администратором.
* При запуске бот пишет в лог, доставляются ли заявки (`notify target ... ✓`).

## Сценарии для грузовиков

* **Заявка (10 шагов, почти всё кнопками):** марка (Isuzu, MAN, KAMAZ, Shacman, Howo, Mercedes-Benz, Volvo,
  Scania, DAF, FAW, Foton, JAC, Dongfeng, Hyundai, Iveco, MAZ, GAZ, Hino + поиск) → модель → год → тип кузова →

* Услуги: диагностика, дизельный двигатель, топливная система/ТНВД, КПП и сцепление, ходовая и рессоры,

## Быстрый старт (Windows)

1. Установите Python 3.11+ (https://www.python.org/downloads/, отметьте «Add python.exe to PATH»).
2. Проверьте `.env` — токен бота уже прописан.
3. Запустите `run.bat` (создаст окружение, установит зависимости и запустит бота).
4. Станьте владельцем: напишите боту `/owner <OWNER_SETUP_CODE>` (код в `.env`),
   либо укажите свой Telegram ID в `OWNER_IDS` (узнать ID — команда `/id`).
5. Добавьте мастеров: 👑 Панель → 👨‍🔧 Мастера → ➕ Добавить мастера → отправьте мастеру одноразовую ссылку.

Linux / сервер:
```bash
python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt && python -m bot
```

## Роли и безопасность

| Роль | Доступ |
|---|---|
| CLIENT | запись, свои заявки, свои автомобили, чат с мастером, AI-помощник |
| MASTER | только назначенные ему заявки: принять, диагностика/ремонт/запчасти, время готовности, комментарий, завершить |
| OWNER | всё: заявки (создание/редактирование/удаление/статусы/мастер/срок), мастера, пользователи и роли, автомобили, статистика, настройки |

* Роль хранится в БД и проверяется **на сервере**: роутеры Owner/Master закрыты фильтром `RoleFilter`,
  а каждая операция с заявкой дополнительно проверяет права (`services.can_manage / can_view`).
  Подделанная кнопка вернёт «⛔ Нет доступа» и запишется в лог.
* Владелец назначается только через `OWNER_IDS` или секретный код (`/owner`, сравнение constant-time).
* Мастер добавляется одноразовой ссылкой-приглашением или владельцем вручную.
* Заблокированные пользователи полностью игнорируются.

## Надёжность

* **Защита от повторной отправки**: у каждого оформления есть idempotency-ключ (уникальный индекс в БД)
  + блокировка на пользователя — двойное нажатие «Подтвердить» не создаст вторую заявку.
* **Уникальные номера**: `NS-000001` из автоинкрементного ID.
* **Анти-флуд**: ограничение частоты нажатий.
* **Ошибки**: глобальный обработчик — пользователь видит понятное сообщение, стек пишется в `logs/bot.log` (ротация 5×5 МБ).
* **Уведомления** не роняют операцию при ошибке доставки; каждое записывается в таблицу `notifications`.
* **История**: каждое действие (кто, когда, что) — в `request_history`.

## База данных

`users, clients, masters, owners, cars, services, requests, request_history, notifications, settings, invites`

Для продакшна: `pip install asyncpg` и `DATABASE_URL=postgresql+asyncpg://user:pass@host/najot`.
Схема создаётся автоматически при запуске. Та же БД может обслуживать сайт NAJOT SERVIS
(заявки с сайта — `source='site'`, клиенты связываются по телефону).

## Масштабирование

* `WEBHOOK_URL=https://bot.example.com` → режим webhook (aiohttp, `WEBHOOK_SECRET` проверяется).
* `REDIS_URL=redis://...` (+ `pip install redis`) → состояния диалогов в Redis, можно запускать несколько процессов.
* PostgreSQL вместо SQLite.

## AI-помощник

С `ANTHROPIC_API_KEY` используется Claude (`AI_MODEL`, по умолчанию `claude-opus-5-5`, структурированный JSON-ответ,
включён серверный fallback-механизм на случай отказа модели). Помощник собирает марку, модель, год, симптомы,
когда началось и доп. признаки, не ставит диагнозов, при опасных симптомах советует не ехать — и предлагает
«📝 Создать заявку» с уже заполненными полями.
Без ключа работает встроенный пошаговый опросник — функция доступна всегда.
Клиенту достаточно просто написать «Машина не заводится» в чат.

## Структура

```
bot/
  __main__.py      запуск, логирование, polling/webhook, обработчик ошибок
  config.py        настройки .env, марки, услуги, статусы
  db.py            модели БД
  i18n.py          все тексты: 🇺🇿 🇷🇺 🇬🇧
  ui.py            клавиатуры, навигация (⬅️ Назад / 🏠 Главное меню)
  services.py      бизнес-логика, права, история, уведомления
  middlewares.py   сессия БД + пользователь, анти-флуд, RoleFilter
  handlers/
    common.py      /start, язык, контакты, о сервисе, /owner, приглашения
    booking.py     мастер оформления заявки (7 шагов + предпросмотр)
    client.py      мои заявки, карточка, история, отмена, чат с мастером
    cars.py        мои автомобили
    master.py      панель мастера + действия персонала (статусы, срок, комментарии)
    owner.py       панель владельца
    ai.py          AI-помощник
```

⚠️ Токен бота был отправлен в чат — после проверки рекомендуется перевыпустить его в @BotFather (`/revoke`)
и обновить `BOT_TOKEN` в `.env`.
